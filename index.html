METHOD

原型驱动的产品工作流

落地于 B 端 APP 场景。不同于传统「先写 PRD 再设计再开发」——先做出能跑通的 H5 原型，再反向生成 PRD，交付开发同学直接喂给 AI。

01

Cursor 建逻辑闭环

用 Cursor 快速搭建可完整跑通的 H5 交互原型，先验证流程与逻辑，而不是先写长文档。

→
02

反复评审打磨

以可点击原型为评审对象，多方对齐交互细节，直到逻辑闭环通过评审。

→
03

Figma 提升品质

结合 Figma 将原型页面优化到产品交付标准，视觉与组件体系对齐线上品质。

→
04

AI 反向生成 PRD

用 AI 补充原型无法承载的信息（规则、边界、埋点等），反向生成结构化 PRD。

→
05

交付开发喂给 AI

将 PRD + 交互原型一并交付。开发同学用这些材料喂给 AI，形成极为高效的研发流程。

传统产品经理路径
  1. 撰写 PRD 文档
  2. 设计出静态稿 / 低保真
  3. 评审时依赖想象与文档
  4. 开发再理解需求与还原
  5. 返工成本高、对齐周期长
VS
我的原型驱动路径
  1. 先做出可跑通的 H5 原型
  2. 用真交互做评审与打磨
  3. Figma 对齐产品级视觉
  4. AI 反向补全并生成 PRD
  5. PRD + 原型喂 AI → 高效开发
TEAM LOOP

设计负责人协作闭环

作为设计部门负责人，我会把一部分原型页面的优化工作交给其他设计师完成，并保证最终回流到可演示原型中。

A

导入 Figma

将原型全部页面按流程顺序导入 Figma，建立统一评审与分工底稿。

B

商定优化范围

与设计师共同确认：哪些页面需优化才能达到产品标准。

C

分发与回收

设计师完成视觉优化后，我将页面再导入原型，使原型完全呈现产品内效果。
